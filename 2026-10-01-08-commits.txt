    # Android apps using btleplug. Closures are now reference counted in the

    # serialized on the object monitor, so an in-flight call always holds its own
    # reference.</li>

    # characteristic discovery reported an error, when the peripheral had no
    # services, or when the peripheral was no longer known to the adapter. Service

    # completes that service without characteristics. (<a href="https://redirect.github.com/deviceplug/btleplug/issues/486">#486</a>)</li>
    # <li>Fix CoreBluetooth panics on late or unexpected discovery callbacks, such as
    # characteristics for included services or descriptors arriving after discovery
    # finished. The panic killed the CoreBluetooth event thread, so every later
    # operation on the adapter hung. (<a href="https://redirect.github.com/deviceplug/btleplug/issues/487">#487</a>)</li>
    # <li>Fix concurrent CoreBluetooth <code>connect()</code>, <code>disconnect()</code>, or
    # <code>discover_services()</code> calls on one peripheral leaving all but the last caller
    # waiting forever. Every concurrent caller now receives the result. (<a href="https://redirect.github.com/deviceplug/btleplug/issues/488">#488</a>)</li>
    # <li>Fix CoreBluetooth reads, writes, subscriptions, and descriptor operations
    # never resolving when services were rediscovered, invalidated by the device, or
    # when peripherals were cleared. Rediscovery keeps in-flight operations on
    # attributes that still exist, operations on attributes that disappear fail with
    # an error, and a services-modified event only drops the invalidated services.
    # On CoreBluetooth, <code>Central::clear_peripherals()</code> now disconnects any
    # peripheral that is still connected. (<a href="https://redirect.github.com/deviceplug/btleplug/issues/489">#489</a>)</li>
    # <li>Fix a Windows deadlock when GATT operations ran concurrently on
    # characteristics of the same service, for example two <code>subscribe()</code> calls
    # joined on one task. (<a href="https://redirect.github.com/deviceplug/btleplug/issues/481">#481</a>)</li>

    # service data section. (<a href="https://redirect.github.com/deviceplug/btleplug/issues/482">#482</a>)</li>
